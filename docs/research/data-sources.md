## 2. 候选职责与缺口

| 数据 | 免费候选 | 必须补做的验证 |
| --- | --- | --- |

| 交易日历 | Baostock；交易所公开日历交叉核对 | 各交易所休市、实际收盘日期及未来年内日历；缺日历不推定休市 |

| 历史 OHLC、成交量/额 | Baostock / 东方财富；腾讯作为交叉核对候选 | 长度、缺失日、历史修订、成交量单位和成交额；腾讯第六列不能直接当人民币成交额 |
| 复权因子 | Baostock / 新浪；东方财富前复权结果交叉核对 | 累计因子方向、快照日锚定、除权/送转/配股样本；只取得前复权价格不足以确认因子正确 |
| 行业、题材与成员 | 东方财富；Baostock 行业作为补充候选 | 成员分页完整性、北交所归属、渠道分类口径、无法取得历史分类时标记未知 |
| 财报及 TTM 输入 | 新浪 / Baostock；交易所或公告资料核对 | 累计/单季、合并/母公司、币种和单位、归母净利润、披露时间、修订版本及北交所 |

选择原则：优先验证 Baostock 承担历史/日历、批量行情渠道承担当日行情、分类渠道手动更新的组合。该组合只是验证方向；证据不足时不宣称任一单源覆盖全 A 股，也不静默跳过北交所。若采用组合来源，后续显式配置、记录实际来源并同步修订接口设计，不沿用示例中的 `available: true` 作为真实配置。

## 3. 低频探测工具

[probe_sources.py](../../backend/tools/probe_sources.py) 仅依赖 Python 3.11 标准库，不安装 AKShare，不执行其自动翻页；已有端点依据缓存源码准备，是否仍有效须由实测确认。

| 项目 | 探测阶段限制 |
| --- | --- |
| 并发 | 单进程串行，文件锁避免重复启动 |
| 请求间隔 | 所有供应商合计至少 10 秒，另加 0～3 秒随机间隔 |
| 预算 | 单轮最多 10 次；每供应商每日最多 20 次；合计每日最多 30 次，北京时间计日 |
| 持久化 | 请求发送前记账，预算/间隔/冷却跨重启保留；损坏状态直接报错，不清零 |
| 重试与冷却 | 无自动重试；403/418/429 至少冷却 24 小时，并遵守更长 Retry-After；网络和其他 HTTP 错误冷却 1 小时；异常响应冷却 24 小时 |
| 隐含请求 | 禁止自动重定向，无自动分页；不使用代理池、换 IP 或伪装身份绕限 |
| 响应与缓存 | 15 秒 socket 超时，响应最多 4 MiB；有效样本保存原始响应与摘要，24 小时内复用 |

预算是本项目的保守探测策略，不是供应商官方额度，也无法保证不会被封禁。不要删除状态文件或启动其他采集器叠加请求。此工具不等于正式同步的频控实现。

以下命令均在项目根目录执行。先预览（不联网、不创建运行状态）：

```bash
python3 backend/tools/probe_sources.py --date 2026-10-29 --source eastmoney --group catalog
```

网络审批恢复后，分组少量执行；日期须换成已确认收盘的交易日：

```bash
python3 backend/tools/probe_sources.py --date 2026-10-29 --source eastmoney --group catalog --execute
python3 backend/tools/probe_sources.py --date 2026-10-29 --source eastmoney --group history --execute
```

支持 `catalog`、`history`、`classification`、`financial`、`factors` 分组；来源支持 `eastmoney`、`sina`、`tencent`。北交所样本优先从目录动态取得，单独运行历史/财务组时使用 24 小时内目录记录，或传入已核对的 `--bse-code`。预算不足或缺少代码时报告 `deferred`，留待后续执行。

原始证据、报告、预算和锁保存在不入 Git 的 `backend/.source-probe/`。`sample_received` 只表示取得可读业务样本；报告固定 `coverageVerified: false`，日期新旧另用 `reachesTarget` 表示。JSON 结果异常、HTML、空数据或目标日以后的行情均不能当作成功。

Baostock 需要其 SDK/TCP 通道，当前工具尚不包含该协议。后续实测应使用其官方 SDK，统一约束 `send_msg` 等实际发包位置；登录、分页和退出均计入预算，不能只在 `query_*` 外层延迟。其余待补测试包括新浪历史压缩数据解码、日历、ST/停牌、总股本、现金流及历史股本口径，不能以已有 HTTP 探测代替。

离线验证命令：

```bash
python3 -m unittest discover -s backend/tools/tests -v
```

## 4. 联网验收与最终选源条件

1. 核对当前文档和访问约束；使用五个板块的当前有效证券，小样本检查实际代码和交易日。
2. 核对至少 140 个交易日的历史窗口，覆盖现有策略最长计算需要；图表更早历史另做范围验证，不填造不足的年均线。
3. 对除权样本核对原价、因子和前复权结果；跨源比较价格、成交量/额、换手率、总市值，列明单位和误差原因。
4. 检查财报年度/季度口径、披露时间和归母净利润，核对 TTM 所需报告链；不能将单季财报指标直接写成累计值。
5. 低频验证分类目录和成员、北交所覆盖、ST/停牌和上市信息。记录真实响应日期、字段、来源及缺失项。
6. 确认批量接口实际返回页大小及总数，再估算全市场初始化、每日增量与重试总量；小样本通过后仍需逐步放量观察，不直接遍历全市场。

请求量约束：假设 5,000 只股票每只每天请求一次，按 10 秒间隔仅等待就约 13.9 小时，两次约 27.8 小时，无法满足收盘后的短时间更新。因此必须先证明当日行情可批量取得，历史仅增量补缺；不能靠提高并发解决。初始化可跨日分批，正式每日预算在实际页大小、时延和覆盖验证后确定。

完成标准：明确免费渠道职责与实际覆盖、必需字段单位、复权/财务口径、缺失项和请求量预算，具备可复核证据。当前联网验收待审批恢复，步骤 1 尚不能标为全部完成；步骤 2～7 未开始。
