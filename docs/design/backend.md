# 后端概要设计

状态：V1 概要设计，随实现更新。当前只开展免费数据源验证，业务服务尚未实现。

本文确定模块职责、数据流和关键取舍；接口字段、策略公式及表结构分别以 [API](../api/README.md)、[策略设计](../strategies/README.md)和 [SQL](../../backend/sql/init.sql)为准，不在此重复。

## 1. 约束与技术方向

- 部署在当前服务器，用户少，采用单体代码库，按职责拆分运行进程。
- 股票、分类和财务资料只使用免费渠道；缓存、增量获取与保守限频优先，覆盖不足如实展示。
- AI 服务可配置地址、模型、密钥及 `chat_completions` / `responses` 协议，兼容服务分别配置实际支持的协议；不预设某家支持两种接口。股票免费数据约束不代表模型调用免费。
- 技术方向为 Python + PostgreSQL，依赖和虚拟环境统一由 uv 管理。Web 框架、数据库访问库与版本在基础工程阶段确定；V1 不增加 Redis 或独立消息队列。

## 2. 模块职责

| 模块 | 职责 |
| --- | --- |
| API 与账号 | 参数校验、统一响应、请求追踪、会话、角色及报告归属校验 |
| 数据渠道 | 证券标识转换、渠道能力声明、行情/分类/财务获取、单位归一、缓存与限频 |
| 同步与调度 | 股票初始化、独立分类任务、历史补齐、收盘同步、五板块预检、进度和日志、重试及恢复 |
| 指标与策略 | 前复权、周期聚合、均线、五类策略、入选理由和固定参考价 |
| 快照与查询 | 构建和发布不可变快照，提供行情状态、筛选、列表、详情和 K 线 |
| 分析服务 | 固定输入快照、技能执行、资料工具、模型适配、结果校验和个人历史，预留报告文档输出 |

同一模块的业务逻辑由 API 和后台任务共用；API 不执行长耗时采集与模型调用。

## 3. 运行形态与数据流

当前服务器部署 API、worker、scheduler 三类进程，共用 PostgreSQL。worker 的同步队列和分析队列分开领取，避免模型慢请求占满同步执行名额；V1 各一个执行名额。scheduler 只登记到期任务和唤醒时间，不负责采集。

```text
浏览器 → API → PostgreSQL（会话、任务、幂等记录、快照、报告）
                    ↑               ↑
             scheduler 登记任务    worker 执行任务
                                    ↓
                       数据渠道 / 指标策略 / AI 服务
```

核心流程：

1. 基础数据：初始化只更新股票基础信息；行业、题材和归属由独立分类任务更新，两者分别记录成功时间。交易日历由行情渠道维护，分类失败或尚未同步不阻塞行情。
2. 收盘同步：固定目标日期 → 五板块预检 → 获取增量及缺失历史 → 校验/复权/策略计算 → 构建快照 → 事务发布。
3. 浏览：列表解析确定快照，详情、图表和分析沿用该快照；未发布数据不可见。
4. 分析：固定用户、股票、快照和策略 → 加载分析技能 → 按需联网检索、读取原文并调用计算工具 → 校验并保存结构化报告；后续可由同一报告生成文档。

具体调度和发布规则沿用 [同步约定](../api/common/sync-policy.md)与[快照约定](../api/common/snapshots.md)。

## 4. 数据渠道与频控

- 每次更新选择一个支持该任务的数据源，执行与重试沿用该渠道；不可用时明确失败。
- 业务层通过统一接口取数，各渠道适配器负责请求和数据格式转换。新增渠道通过实现接口并注册接入。
- 所有对同一供应商的实际请求共用限频和冷却机制；遇到限流暂停访问，重试次数受限。
- 优先使用缓存、批量和增量更新，减少重复请求；频率和额度根据渠道实测确定。

渠道能力、实测结果和探测参数见[免费数据源验证](../research/data-sources.md)。

## 5. 数据存储与一致性

沿用现有 17 张表：账户与会话、证券与分类、交易日历、任务、快照与日线修订、策略信号、任务日志与调度触发、幂等请求、财报、分析资料及结果。初始化 SQL 维护完整结构；结构变更按[项目数据库约定](../../AGENT.md#数据库约束)同步更新已部署数据库。

- 保存未复权 OHLC、原始成交量/额和复权因子；按快照日期统一前复权。缺失值保留 `null`，单位在渠道边界转换。
- 日线以“快照 + 股票 + 日期”保存修订；读取时只解析该快照版本可见的最新修订。发布时冻结历史范围、复权、分类及策略版本，避免新数据改写旧页面。
- 构建过程可分批落库，发布使用短事务，保证行情与策略结果一同可见。失败快照不改变最新有效快照。
- 保留可复查的来源、获取时间、披露时间和财报口径。历史行情快照与随后取得的财务资料时间分别展示，禁止将后取得资料解释为历史已知信息。
- 快照保存和失败构建清理策略待全市场容量测算后确定，不提前删除被历史报告引用的数据。

## 6. 后台任务与恢复

沿用 [任务契约](../api/common/tasks.md)，以数据库任务表作为持久化队列。

- 领取时用短事务锁定到期任务并写入租约；长任务续租，完成写入校验租约归属，防止旧 worker 覆盖新执行者。
- 进程异常退出后回收过期租约，按任务阶段恢复；批次写入幂等，不能只把状态改回排队后重复产生业务结果。
- 同步任务串行，分析按用户和输入范围去重；提交幂等记录与任务创建在同一事务提交。
- 等待行情或频控时保存下次执行时间并释放执行名额；限流熔断不可通过重建任务绕过。
- 数据就绪超时与网络失败分别记录；用户退出、关闭页面或会话过期不取消已受理任务。

## 7. AI 与权限边界

- 拟采用“智能体框架 + 本地技能 + 工具适配”的结构。框架优先评估 DeepAgents，具体选型以双协议模型兼容、技能加载和工具调用验证为准。
- 首版提供一个股票分析技能，以 `SKILL.md` 和配套资料维护基本面、筹码及买卖条件的分析方法和报告要求。技能由运行层加载，工具权限与执行限制由后端管理。
- 联网通过可替换的检索和网页读取工具提供，供智能体按需查询公告、财报及相关新闻；优先采用交易所、公司公告等原始资料，保留引用原文及来源时间，取得资料不足时明确说明。
- 模型适配层分别支持 Chat Completions、Responses；逐服务验证工具调用能力，能力受限时采用预先准备资料的生成流程。工具复用已有数据渠道和频控，运行次数、超时和费用设上限。
- 财务指标、策略条件和筹码估算由代码或核验来源提供，模型组织分析；报告通过结构校验，来源引用实际资料，并保留技能、模型与计算版本。
- 后续文档功能基于已保存的结构化报告和图表，用模板生成 Markdown、Word 或 PDF；生成结果关联原分析及输入版本，沿用报告所属用户的访问权限。

框架候选的当前版本能力尚未完成在线核验；本阶段只记录设计方向，不安装框架或实现报告导出。

密码使用成熟哈希库，会话令牌服务端可撤销、数据库只保存摘要。后端执行角色和资源归属校验，管理员也不能读取他人分析报告。密钥通过服务器配置注入，日志不写密钥、密码或会话令牌。

## 8. 部署与验证

复用现有 PostgreSQL Compose；应用进程由统一部署配置管理。前端与 `/api/v1` 同源，正式公网入口使用 HTTPS；数据库仅绑定本机。健康检查区分进程存活、数据库可连接与业务数据是否已准备。

验证重点为策略边界与无未来数据、五板块和单位口径、幂等与权限、任务崩溃恢复、限流熔断、快照不可变及协议适配。上线前验证一次完整初始化/同步/浏览/分析流程和全市场请求量、时长、磁盘占用；运维说明覆盖启动、日志、备份与恢复。

## 9. 实现顺序与待定项

数据源验证 → 基础工程与账号 → 同步任务 → 策略和快照 → 页面查询联调 → AI 分析 → 部署验收。各阶段同步更新本概要设计中的已确认决策；不在本轮实现后续阶段。

当前待定：免费渠道的五板块实际覆盖、历史复权和财务口径；免费联网检索渠道的可用性与限频；全量初始化预算与存储规模；框架/依赖版本；模型服务地址、模型名称和预算。AI 协议范围、免费股票数据和当前服务器小规模部署已由用户确认。
