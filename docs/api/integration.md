# 前端对接说明

[接口总览](README.md) · [通用约定](common/conventions.md)

响应先从统一外层提取 `data`，再转换为页面模型；`requestId` 保留用于排查请求问题。

1. 登录后调用 `/auth/me`、`/market/status`；无快照时展示数据准备状态，管理员可进入数据管理。
2. 有快照后获取策略说明和筛选选项，再查询机会列表；列表、详情、图表沿用快照 ID。
   个股分析入口通过`GET /stocks?search=名称或代码`搜索完整目录；搜索不受入选条件限制，进入详情后固定实际快照。通用买卖建议提交时省略策略，历史查询传`kind=trade&strategy=general`；具体策略仅使用已入选信号，切换模式不混用历史。
3. 进入 AI 分析先恢复本人任务和成功历史，提交后按 `status` / `stage` 展示阶段并轮询详情；终态停止轮询。进行中冲突查询原任务，失败重试使用新 key，生成新报告时仍可查看旧历史。报告分别展示行情日期、资料获取时间、来源及缺失说明。
4. 管理员新增用户、修改密码；同步进度集中在任务列表，点击查看详情再展示预检、等待原因和日志。轮询只更新任务列表，任务成功后刷新行情状态；准备阶段不显示股票百分比，逐股处理后使用stockProgress对应的progress，不依赖页面计时器推进。

前端已使用真实HTTP数据层：会话由服务器校验，列表使用服务器分页和汇总，K线及均线直接采用接口结果，任务只轮询不由浏览器推进。股票路由使用稳定`stockId`，所有后续请求沿用列表解析出的快照。

换手率和总市值使用预设区间下拉框，所选区间转换为现有的 `minTurnover` / `maxTurnover`、`minMarketCap` / `maxMarketCap` 参数，包含上下边界；选择“不限”时省略两侧参数。市值下拉选项及页面网址使用亿元，调用正式 API 时须将区间边界乘以 `100000000` 转为元；接口返回的总市值展示时做相反转换。

正式页面已移除演示场景与虚构行情。`coverage=unavailable`的筛选项禁用；缺失值保持未知，不以0代替。当前覆盖沪深四板块，北交所明确显示暂不可用。

行业、题材下拉框均支持输入名称关键词定位选项；选中后按对应分类筛选，刷新保留选择。

AI 报告默认展示 `overview.decision` 的当前建议与一句理由，再按类型展示一条机会/风险、筹码图或参考价。`metrics`、`sections` 和来源详情放入按需展开区域，避免让用户通过大量指标自行推导结论。
