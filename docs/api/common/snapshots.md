# 数据快照约定

[接口总览](../README.md)

- `snapshotId` 标识一次已发布的收盘行情与策略结果；快照包含 `id`、`dataDate`、`publishedAt`、`adjustment: "qfq"`、`strategyVersion`、`boards`（本次覆盖板块）、`source`（所选渠道）及`dataProvenance`（按字段标识实际上游）。
- 机会列表、筛选项、个股详情、K 线和分析请求可指定 `snapshotId`；省略时采用最新已发布快照。未知 ID 返回 `404 SNAPSHOT_NOT_FOUND`，尚无快照返回 `409 DATA_NOT_READY`。
- 前端取得列表快照后，后续详情和 K 线应沿用该 ID，保持价格、均线和信号处于同一数据与复权口径。
- 已发布快照的行情、策略结果、行业题材归属及复权口径保持稳定。同一交易日重新同步可产生新快照，既有快照仍可查询。
- “最新快照”先按 `dataDate` 取最新交易日，同日取最后发布的一份；补同步较早日期不会让默认数据日期倒退。
- 仅完整同步成功后发布新快照；等待、跳过或失败均保留原有效数据。`dataDate` 是实际数据日期，不能以请求当天代替。
- 初始化仅准备股票基础信息；行业、题材归属由独立分类任务更新，更新范围见[数据管理](../../requirements.md#2-数据管理)。只有收盘同步才产生机会列表使用的快照，分类未同步不阻塞收盘任务。
- 最新收盘快照可复用构建时已取得的分类；`catalogAsOfAt`记录分类资料截至时间，可能晚于行情日期，页面分别展示。手动刷新分类只影响后续新快照。历史回补不把后取得的当前分类当作当时已知归属，无法取得时标记未覆盖。
- `boards`随快照固定。当前上线四板块，后续扩展北交所不会改变旧快照；筛选未覆盖板块返回`FILTER_UNAVAILABLE`。
